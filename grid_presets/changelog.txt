Changelog for Grid Presets
===============================


## 2.2.0

- Copy rows: a Copy button copies the Grid's rows, with a headings row, as a table and tab separated text
  - Pastes into Excel/Google Sheets (line breaks stay in their cells), or back into a Grid, where the headings map the columns by name
  - Values are copied as readable text: option labels, "Yes"/"No" toggles, ticked options, relationship titles (one per line), rich text as plain text
- Paste reads relationship titles one per line, so titles containing commas copy and paste correctly

## 2.1.0

- Paste rows: a Paste button under each Grid takes a copied table (web page, Excel, Google Sheets) or tab/space separated text
  - Preview before pasting, with "Add after existing rows" or "Replace existing rows"
  - Columns map by position, or by name when the first row matches the Grid's column labels; each column's source can be changed
  - "Swap rows and columns" for spec-sheet layouts (switched on automatically when the first column holds the Grid's column labels)
  - Matches values to options: selects, EE dropdowns, MX Select Plus, checkboxes, radios, selectable buttons, toggles, and relationships by entry title or ID
  - Values with no matching option are highlighted and left empty
  - Merged cells and line breaks in cells are kept
- Loading a preset (and pasting) now stops at the Grid's maximum rows

## 2.0.0

Requires ExpressionEngine 7. Use 1.4.4 for EE2-EE6.
Run the add-on update in the CP (Add-ons) to convert existing presets.

- Grid and File Grid fields inside Fluid fields, including ones added after the page loads
- Each copy of a Grid on the page gets its own preset buttons (e.g. the same Grid repeated in a Fluid field)
- Presets are saved as JSON in a larger (MEDIUMTEXT) column: no more PHP max_input_vars or 64 KB limits
- Existing presets are converted to JSON by the update
- Saving checks the field is a Grid or File Grid field
- Members without access to the add-on no longer get errors (the buttons are just not shown)
- Relationships load properly (EE7's React field is re-rendered with the entries selected, showing titles and staying editable); previously they saved empty on EE7
- Rich Text (RedactorX, Redactor, CKEditor) content loads into the editor, including deferred editors
- MX Select Plus (Chosen) and EE's React dropdowns show the loaded values; missing select options are added, for multi-selects too
- Channel Images Select widgets are rebuilt with the loaded images (thumbnails need Channel Images Select 1.4.2+)
- Loading no longer triggers a burst of EE form validation requests (validation is paused while rows are filled)
- Save selects the new preset, and asks for rows when the Grid is empty
- Ready for jQuery 4 (no positional selectors)
- Removed: EE2-EE6 support, the EE3 script, and the pre-1.2 settings migration (update to 1.4.4 first to keep presets from 1.1 or earlier)

## 1.4.4

- Fixed loading older presets saved by column position (rows were added but left empty)
- Fixed a JS error when loading a preset into a Grid with columns added after it was saved (toggle/colour picker)
- Fixed new presets overwriting preset 10 once a field had 10 or more presets
- Fixed checkboxes, radios and selectable buttons loading into the wrong options, and defaults being unchecked
- Fixed toggles only loading "on" (they can now be loaded "off" when the default is on)
- Fixed select values containing quotes breaking the load, and missing options being added with the wrong value
- Security: preset names and loaded values are escaped (preset names could inject HTML into the CP)
- Security: stored presets are unserialized as arrays only
- Performance: no database queries on every CP page; presets are only requested on publish pages with Grid fields
